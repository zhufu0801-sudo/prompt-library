# 数据库结构与数据流

SQLite / Cloudflare D1，Drizzle 负责结构迁移，应用查询使用绑定参数。当前 10 张表：

| 表 | 用途 | 主要关系 |
| --- | --- | --- |
| categories | 模块 | templates.category_id |
| sources | 来源、许可与版本 | templates.source_id |
| templates | 提示词正文、译文、状态 | 分类、来源 |
| tags | 去重标签词典 | template_tags |
| template_tags | 模板标签关联 | 复合主键 |
| template_fields | 可填写字段、类型、默认值、最大选择数 | templates |
| field_suggestions | 推荐词与条件字段 | template_fields |
| favorites | 访客收藏 | 访客散列 + 模板 |
| plans | 方案与锁定状态、最终输出 | 访客散列 + 模板 |
| content_versions | 已应用内容版本 | 内容哈希 |

表单值和锁定状态是用户方案的灵活结构，保存在 JSON 列；模板、字段和推荐词本身分表，方便独立查询和维护。

## 数据来源

`JSON 内容文件 → scripts/build-content.mjs 校验 → 分批 upsert 种子 → SQLite/D1 → API → 网页`

网站列表和详情真正读取数据库。30 个自有模板按模块维护，每个都有 5 个可编辑字段。279 条上游记录保留独立 namespace `aishort-*`，自有记录为 `custom-*`。

新增或修改 JSON 后，构建得到新的内容版本。线上首次请求按版本同步；同一版本跳过。每个模板的正文、标签、字段与推荐词在同一 D1 batch 中原子更新。用户方案与收藏表不在内容同步范围内。

内容以版本控制中的 JSON 为权威维护源。直接改 D1 中的模板只适合临时诊断；下次内容版本同步会按照 JSON 更新。如果需要线上编辑后台，应另外增加审计与回写流程，不应让浏览器直接运行 SQL。

## 索引与约束

主键和唯一 slug 避免重复。模板按分类/状态和来源类型/状态建索引；字段、词库按父记录建索引；方案按访客与更新时间查询。外键关联开启级联清理字段和标签关联，保留用户方案的模板引用。

当前记录量 309，关键词搜索使用参数化 LIKE 和标签关联。百分号、下划线和反斜线均按字面转义。未来量级提升后可追加 FTS5 迁移，当前不引入外部搜索服务。

## 导入与迁移

- schema-only 迁移位于 `drizzle/`；不把大量种子塞入 migration。
- `database/seed.sql` 可单独检查、导入和版本审查。
- 原始上游快照、规范化条目和 manifest 分开。
- 增量更新以上游固定 commit 为依据；新增自有内容不覆盖上游 ID。
- 下架用 `archived`；删条目不代表自动删除数据库记录。

## 当前验收基线

10 个模块，309 条模板（30 原创、279 导入），150 个字段，387 条推荐词，145 个去重标签。

参考 SQLite 检查了外键、完整性与分类查询索引。云端部署与本地数据库是独立实例，不能把本地测试记录视为线上用户数据。
